# PR Monitor (GitHubChecker)

指定したリポジトリのオープン PR について、**最新コミットの Actions の結果**と
**レビュー結果のサマリ**を1画面で監視するローカル Web ダッシュボード。

- 依存パッケージ **ゼロ**（Node 20+ の標準機能だけ）。`npm install` は不要。
- 認証は **`gh` CLI のトークンを使い回す**ので、トークンを別途管理しなくてよい。
- ビルド工程なし。ファイルを保存してブラウザを再読み込みすれば反映される。

## 起動

**`pr-monitor.cmd` をダブルクリック**（またはショートカットを作って実行）でサーバが起動し、
ブラウザが開く。**既に起動している場合は二重に立てず、ブラウザで開くだけ**で終わる。

コマンドから起動する場合:

```sh
node src/server.mjs        # http://127.0.0.1:8787/ が開く
npm run dev                # ソース変更で自動再起動 (node --watch)
node src/server.mjs --no-open   # ブラウザを自動で開かない
```

前提: `gh auth login` 済みであること（`repo` スコープが必要）。
`gh` を使わない場合は環境変数 `GITHUB_TOKEN` を設定する。

## 設定 (`config.json`)

保存すると**次の取得時に反映**される（サーバ再起動は不要）。

| キー | 既定値 | 意味 |
| --- | --- | --- |
| `port` | `8787` | ダッシュボードのポート |
| `repos` | `[]` | 監視対象。`"owner/name"` の配列（GitHub の URL を貼っても可） |
| `maxPrsPerRepo` | `100` | 1リポジトリあたりの取得上限（更新の新しい順） |
| `cacheSeconds` | `45` | この秒数以内の再表示は API を叩かない |
| `refreshSeconds` | `60` | 画面の自動更新間隔。`0` で自動更新オフ |
| `excludeAuthors` | `[]` | 常に除外する作成者（例 `["dependabot[bot]"]`） |
| `excludeDrafts` | `false` | Draft PR を除外する |

bot や Draft は画面のチェックボックスでも一時的に隠せる（絞り込みはブラウザに保存される）。

**監視リポジトリは画面からも編集できる。** 「監視リポジトリ（n）」パネルを開いて1行1リポジトリで
書き換え、「保存して再取得」を押すと `config.json` が書き換わり、そのまま再取得する。
`owner/name` でも GitHub の URL でもよく、重複は自動で除かれる（書き込みはローカルからのみ受け付ける）。

## 画面の見かた

右上で **カンバン / リスト** を切り替える（選択はブラウザに保存される）。

### カンバン（ピボット）

行と列の軸を自由に差し替えられる。「軸」の行で 列 / 行 を選び、`⇄` で入れ替える。

| 軸 | 内容 |
| --- | --- |
| 状態 | 対応が必要 / 待ち / マージ可 / その他（既定の列。0件の列も出る） |
| Actions | CI失敗 / CI実行中 / CI中断 / CI成功 / CIなし |
| レビュー | 変更要求 / レビュー待ち / コメントのみ / 承認済み / 未レビュー |
| リポジトリ・作成者・ベースブランチ・レビュー依頼先 | 実際に存在する値だけが並ぶ（件数の多い順） |
| 自分/他人・Draft | 2値 |
| （なし） | 行に選ぶと1段のカンバン。列に選ぶと1列にまとめる |

例: 列=状態 / 行=リポジトリ でリポジトリ横断の進捗、列=Actions / 行=作成者 で誰の PR が
落ちているか、といった見方ができる。軸を増やしたいときは `public/app.js` の `DIMENSIONS` に
1エントリ足すだけで選択肢に出る。

カードの左端の色は**列とは別に深刻さ**を示す（赤=CI失敗かコンフリクト、オレンジ=変更要求、
黄=実行中/レビュー待ち、緑=承認済み+CI通過）。

### リスト

一覧は**バケット**でグループ化され、上から順に並ぶ。

| バケット | 条件 | 意図 |
| --- | --- | --- |
| 対応が必要 | CI 失敗 / 変更要求 / コンフリクト | 誰かが手を動かさないと進まない |
| マージ可 | 承認済み かつ CI 通過 かつ Draft でない | 取り込める |
| 待ち | CI 実行中 / レビュー待ち | 待っていれば動く |
| その他 | 上記以外（Draft、レビュー依頼前など） | |

- **Actions**: 最新コミット (`HEAD`) に紐づくチェックの集計。`成功数/対象数`（skip は分母から除外）。
  カード/行をクリックすると失敗・実行中を先頭にした全チェックが出る（GitHub の該当ジョブへリンク）。
- **レビュー**: レビュアーごとの**最新**レビューを集計（承認 / 変更要求 / コメント / 依頼中）。
  ブランチ保護でレビュー必須になっていない場合 `reviewDecision` が `null` になるため、
  そのときは実績（誰が何を出したか）から状態を決めている。
- 詳細には「最後のレビューより後に push があるか」も出る（対応済みらしさの目安）。

キーボード: `r` で再取得。カード/行のクリック、または Enter / Space で詳細の開閉。

## 補助コマンド

```sh
npm run dump                          # 整形後の JSON をそのまま出力
npm run dump -- --stats               # 集計だけ
npm run dump -- --repo Dealer --pr 449   # 特定 PR の内訳（判定の理由を追うとき）
npm run smoke                         # 起動中のサーバに繋いで描画が通るか検証
```

`npm run smoke` は最小限の DOM スタブ上で `public/app.js` を実行する。
カンバン（軸の差し替え・入れ替え含む）、リスト、詳細の開閉、リポジトリ編集欄まで一通り通す。
見た目は検証できないが、UI をいじった後にクラッシュや件数の異常を素早く拾える。

## API（画面が使っているもの）

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/dashboard` | PR一覧と集計。`?refresh=1` でキャッシュ無視 |
| POST | `/api/config/repos` | `{"repos":["owner/name", …]}` を保存 |
| GET | `/api/ping` | 二重起動の判定用 |

`127.0.0.1` のみで待ち受け、書き込みは Origin がローカルのときだけ受け付ける。

## 既知の癖

- GitHub の `mergeable`（コンフリクト判定）は非同期に計算されるため、初回の問い合わせでは
  `UNKNOWN` が返ることがある。同じ HEAD コミットの直近の確定値をサーバ側で覚えて埋め戻している。
- Draft PR ではワークフローが動かない設定のこともあり、その場合 Actions は「CIなし」になる。
