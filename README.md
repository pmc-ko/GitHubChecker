# PR Monitor (GitHubChecker)

[![CI](https://github.com/pmc-ko/GitHubChecker/actions/workflows/ci.yml/badge.svg)](https://github.com/pmc-ko/GitHubChecker/actions/workflows/ci.yml)

指定したリポジトリのオープン PR と Issue について、**最新コミットの Actions の結果**・
**レビュー結果のサマリ**・**Issue との紐づき**を1画面で監視するローカル Web ダッシュボード。

- ダッシュボード本体は依存パッケージ **ゼロ**（Node 20+ の標準機能だけ）。`npm install` は不要。
  デスクトップアプリとして使いたいときだけ Electron を入れる（後述）。
- 認証は **`gh` CLI のトークンを使い回す**ので、トークンを別途管理しなくてよい。
- ビルド工程なし。ファイルを保存してブラウザを再読み込みすれば反映される。

## 起動

**`pr-monitor.cmd` をダブルクリック**（またはショートカットを作って実行）でサーバが起動し、
ブラウザが開く。**既に起動している場合は二重に立てず、ブラウザで開くだけ**で終わる。

コマンドから起動する場合:

```sh
node src/server.mjs        # http://127.0.0.1:8787/ が開く
npm run dev                # ソース変更で自動再起動 (node --watch)
node src/server.mjs --no-open   # ブラウザを自動で開かない
```

前提: `gh auth login` 済みであること（`repo` スコープが必要）。
`gh` を使わない場合は環境変数 `GITHUB_TOKEN` を設定する。

## 停止

**`pr-monitor-stop.cmd` をダブルクリック**でサーバが終了する。起動していなければ何もしない
（どちらの場合も終了コード 0）。起動したウィンドウをそのまま閉じても止まる。

```sh
npm run stop               # 同じことをコマンドから
```

ポートは起動側と同じ経路（環境変数 `PORT` → `config.json`）で解決するので、
`port` を変えていても指定しなおす必要はない。

## デスクトップアプリ（Electron）

**独立したアプリとして扱いたいとき用**。ブラウザのタブではなく専用ウィンドウ + タスクトレイ常駐 +
デスクトップ通知になる。ダッシュボードの中身（`src/` と `public/`）は共通で、殻だけが `electron/`。

```sh
npm install          # 初回だけ（electron を devDependency として入れる）
npm run app          # 専用ウィンドウで起動
```

`pr-monitor-app.cmd` をダブルクリックでも起動する。**Electron が入っていなければ Edge/Chrome の
アプリモード**（タブもアドレスバーも無いウィンドウ）にフォールバックするので、`npm install`
していない環境でも「独立したアプリ」として開ける。

- ローカルサーバは**アプリが自分で起動する**（Electron 同梱の Node を使うので、この PC に Node
  が無くても動く）。すでに `pr-monitor.cmd` で起動済みならそれを使い、終了時にも止めない。
- **開始と終了はアプリの実行・ウィンドウを閉じる操作に連動する。** ウィンドウを閉じるとアプリが
  終了し、自分で起動したサーバも止まる（トレイに残らない）。トレイアイコンは動作中の
  ショートカット（表示 / 今すぐ更新 / ブラウザで開く / 設定ファイル / 終了）。
- トレイのツールチップに件数、**新しく「対応が必要」になった PR は通知**で知らせる（`electron/watch.mjs`）。
- リンク（PR / チェック / Issue）は既定のブラウザで開く。`F5` 再読み込み、`F12` 開発者ツール。

```sh
npm run app:package  # 配布用フォルダを dist/ に作る（@electron/packager を都度取得）
npm run app:icon     # electron/icon.png と icon.ico を描き直す
```

## 設定 (`config.json`)

`config.json` は**環境ごとの設定なので git 管理外**。`config.example.json` をコピーして作る
（無くても既定値で起動し、監視リポジトリは画面から追加できる）。

```sh
cp config.example.json config.json
```

**そもそも `config.json` を手で編集する必要はない。** 監視リポジトリは「監視リポジトリ」パネル、
取得に関わる設定は**「取得の設定」パネル**から変えられる（変更するとその場で保存される）。

| パネル | 変えられるもの |
| --- | --- |
| 監視リポジトリ | 候補の追加・削除、監視の ON/OFF（`repos` / `disabledRepos`） |
| 取得の設定 | 自動更新の間隔、キャッシュ、Issue も取得、PR/Issue の取得上限、Draft を取得しない、除外する作成者、ポート |

**置き場所**は使い方で変わる。画面の「監視リポジトリ」パネル下部に**実際のパスが出る**ので、
迷ったらそこを見る（アプリ版はトレイの「設定ファイルを開く」からも開ける）。

| 使い方 | 場所 |
| --- | --- |
| ブラウザ版 / `npm run app`（開発） | リポジトリ直下の `config.json` |
| **exe 版（Release の zip）** | **`PRMonitor.exe` と同じフォルダ**（初回起動時に雛形を作る） |
| exe を書き込めない場所に置いた場合（Program Files 等） | `%APPDATA%\github-pr-checker\config.json` に退避 |

exe の中（`resources\app`）には置かない。アプリを差し替えても設定が消えず、書き込み権限の
問題も起きないようにするため。場所を明示したいときは環境変数 `PR_MONITOR_CONFIG` で指定できる。

保存すると**次の取得時に反映**される（サーバ再起動は不要）。

| キー | 既定値 | 意味 |
| --- | --- | --- |
| `port` | `8787` | ダッシュボードのポート |
| `repos` | `[]` | 監視対象。`"owner/name"` の配列（GitHub の URL を貼っても可） |
| `disabledRepos` | `[]` | 監視を止めているリポジトリ。候補として残るだけで取得しない（画面のチェックを外すとここに移る） |
| `maxPrsPerRepo` | `100` | 1リポジトリあたりの取得上限（更新の新しい順） |
| `includeIssues` | `true` | Issue とマイルストンも取る（PRとの紐づき・進捗グラフ用）。`false` で問い合わせ自体をしない |
| `maxIssuesPerRepo` | `100` | 1リポジトリあたりの Issue 取得上限。足りないときは画面上部に警告が出る |
| `cacheSeconds` | `120` | この秒数以内の再表示は API を叩かない |
| `refreshSeconds` | `300` | 画面の自動更新間隔。`0` で自動更新オフ |
| `excludeAuthors` | `[]` | 常に除外する作成者（例 `["dependabot[bot]"]`） |
| `excludeDrafts` | `false` | Draft PR を除外する |

bot や Draft、**リポジトリごとの表示**は画面のチェックボックスで一時的に隠せる
（絞り込みはブラウザに保存される。こちらは取得は止めない＝件数のカウントは変わる）。
リポジトリのチェックを全部入れる/全部外すと「絞り込みなし（全部表示）」に戻る。

**監視リポジトリは画面からも編集できる。** 「監視リポジトリ（n）」パネルに候補が
**チェックボックス**で並ぶ。

- **チェックを外す = 取得しない**（`config.json` の `disabledRepos` に移るだけなので、
  あとで戻せる）。チェックの変更はその場で保存され、そのまま再取得する。
- **追加・削除**は下の入力欄に1行1リポジトリで書いて「保存して再取得」。`owner/name` でも
  GitHub の URL でもよく、重複は自動で除かれる。入力欄にはチェックを外したものも含めて
  **候補すべて**が並ぶ（欄から消すと候補ごと消える）。

見出しは `有効/候補` の形になる（例: `監視リポジトリ（5/6）`）。書き込みはローカルからのみ受け付ける。

## 画面の見かた

右上で **カンバン / リスト** を切り替える（選択はブラウザに保存される）。

### カンバン（ピボット）

行と列の軸を自由に差し替えられる。「軸」の行で 列 / 行 を選び、`⇄` で入れ替える。

| 軸 | 内容 |
| --- | --- |
| 状態 | 対応が必要 / 待ち / マージ可 / その他 / Issue（PRなし）（既定の列。0件の列も出る） |
| Issue連携 | Issueのみ / Issue+PR / PRのみ の3パターン（0件でも出る） |
| マイルストン | PR 自身のマイルストン。無ければ紐づく Issue のものを使う |
| ラベル | **1件が複数ラベルを持つ場合は各ラベルの列に出る**ので、カード総数は件数より多くなる |
| Actions | CI失敗 / CI実行中 / CI中断 / CI成功 / CIなし |
| レビュー | 変更要求 / レビュー待ち / コメントのみ / 承認済み / 未レビュー |
| リポジトリ・作成者・ベースブランチ・レビュー依頼先 | 実際に存在する値だけが並ぶ（件数の多い順） |
| 自分/他人・Draft | 2値 |
| （なし） | 行に選ぶと1段のカンバン。列に選ぶと1列にまとめる |

例: 列=状態 / 行=リポジトリ でリポジトリ横断の進捗、列=Actions / 行=作成者 で誰の PR が
落ちているか、といった見方ができる。軸を増やしたいときは `public/app.js` の `DIMENSIONS` に
1エントリ足すだけで選択肢に出る。

カードの左端の色は**列とは別に深刻さ**を示す（赤=CI失敗かコンフリクト、オレンジ=変更要求、
黄=実行中/レビュー待ち、緑=承認済み+CI通過）。

**カードは2段**で高さを詰めている。

| 段 | 中身 |
| --- | --- |
| 1段目 | 状況アイコン（CI / レビュー / Issue連携 / コンフリクト）+ CI 進捗バーと `通過/対象` + 番号・担当・更新時刻 |
| 2段目 | タイトル（全文。折り返す）+ マイルストン・Issue・ラベルのチップ |

アイコンは**形で区別**でき、語はマウスを乗せると出る（詳しい内訳はクリックで開く詳細）。

### リスト

一覧は**バケット**でグループ化され、上から順に並ぶ。

| バケット | 条件 | 意図 |
| --- | --- | --- |
| 対応が必要 | CI 失敗 / 変更要求 / コンフリクト | 誰かが手を動かさないと進まない |
| マージ可 | 承認済み かつ CI 通過 かつ Draft でない | 取り込める |
| 待ち | CI 実行中 / レビュー待ち | 待っていれば動く |
| その他 | 上記以外（Draft、レビュー依頼前など） | |
| Issue（PRなし） | オープンな PR が紐づいていない Issue | 未着手 |

- **Actions**: 最新コミット (`HEAD`) に紐づくチェックの集計。`成功数/対象数`（skip は分母から除外）。
  カード/行をクリックすると失敗・実行中を先頭にした全チェックが出る（GitHub の該当ジョブへリンク）。
- **レビュー**: レビュアーごとの**最新**レビューを集計（承認 / 変更要求 / コメント / 依頼中）。
  ブランチ保護でレビュー必須になっていない場合 `reviewDecision` が `null` になるため、
  そのときは実績（誰が何を出したか）から状態を決めている。
- 詳細には「最後のレビューより後に push があるか」も出る（対応済みらしさの目安）。

### Issue との突き合わせ（3パターン）

PR の「Fixes #123」等（GraphQL の `closingIssuesReferences`）で Issue と紐づけ、次の3つで見えるようにしている。

| パターン | 見え方 |
| --- | --- |
| ○ Issueのみ | PR が無い Issue。**Issue 自身が1件として一覧に並ぶ**（バケット「Issue（PRなし）」） |
| ◉ Issue+PR | PR 側に `Issue #123` のチップが付く（Issue は重複して並べない） |
| ◍ PRのみ | Issue に紐づいていない PR |

マイルストンとラベルはカード/行にチップで出る（`◈` がマイルストン）。
「Issue除外」で Issue を一覧から隠せる（絞り込みはブラウザに保存される）。

### 進捗

「進捗」パネルに3つ。**どのグラフも件数と % を文字で併記**し、色だけに意味を持たせていない。

| グラフ | 内容 |
| --- | --- |
| Issue連携の内訳 | いま表示中のものを3パターンで積み上げ（凡例に件数と%） |
| マイルストン進捗 | クローズ済み Issue ÷ Issue 全体。オープンなマイルストンのみ、期限超過は `⚠` 付き |
| ラベル別 | 件数の多い順に上位8件。内訳の色は Issue連携と同じ。省略分は件数を添えて表示 |

**マイルストンの % は GitHub の画面と一致しないことがある。** GitHub の `progressPercentage` は
PR も母数に入れるため、ここでは表示している件数と一致する「Issue だけの割合」を出している
（GitHub 側の値はバーの `title` に出る）。マイルストン進捗はリポジトリの絞り込みだけ反映する。

キーボード: `r` で再取得。カード/行のクリック、または Enter / Space で詳細の開閉。

### 画面サイズ（ウルトラワイド前提の詰め方）

**2560×720 のような「横に広くて縦が無い」全画面運用**を想定して作ってある。

- 縦 860px 以下では余白と文字を詰める（KPI は1行、進捗のカードは中身をカード内スクロール）
- 「進捗」「監視リポジトリ」「取得の設定」の**開閉を覚える**。低背の画面では初回は進捗を畳んだ
  状態で始まる（一覧に高さを回すため）
- カンバンの列は**画面の残り高さぶんだけ伸びて、列ごとにスクロール**する（列見出しは残る）。
  上のパネルを開閉すると残り高さを測り直す
- 横 1800px 以上では1列の幅を 480px で止める（間延びさせない）。列が増えるときは横スクロール

## 補助コマンド

```sh
npm test                              # GitHub を叩かないテスト（固定データ + DOM スタブ）。CI もこれ
npm run dump                          # 整形後の JSON をそのまま出力
npm run dump -- --stats               # 集計だけ
npm run dump -- --repo myrepo --pr 123   # 特定 PR の内訳（判定の理由を追うとき）
npm run dump -- --repo myrepo --issue 45  # 特定 Issue の内訳
npm run dump -- --stats               # 集計 + マイルストンの進捗
npm run smoke                         # 起動中のサーバに繋いで描画が通るか検証
```

```sh
npm run icons                         # アイコン（Material Symbols）のパスを再生成
```

アイコンは **Google の Material Symbols**（Apache-2.0）。`public/icons.js` にパスデータを
埋め込んで使うので、実行時にフォントや CDN を読まない（オフラインでも出る）。増やすときは
`tools/make-icons.mjs` の `ICONS` に名前を足して `npm run icons`。

テストは2段階。どちらも最小の DOM スタブ（`test/dom-stub.mjs`）の上で `public/app.js` を動かす。

| コマンド | 何を見るか |
| --- | --- |
| `npm test` | **固定データ**（`test/fixture.mjs`）で判定と描画を検証。GitHub もトークンも要らないので CI で回る |
| `npm run smoke` | **実データ**で描画が通るか。起動中のサーバに繋ぐ（トークンが必要） |

`npm run smoke` はカンバン（軸の差し替え・入れ替え含む）、リスト、詳細の開閉、リポジトリ編集欄まで
一通り通す。見た目は検証できないが、UI をいじった後にクラッシュや件数の異常を素早く拾える。

## API（画面が使っているもの）

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/dashboard` | PR一覧と集計。`?refresh=1` でキャッシュ無視 |
| POST | `/api/config/repos` | `{"repos":[候補すべて], "disabledRepos":[止めるもの]}` を保存（`disabledRepos` 省略時は全部有効） |
| POST | `/api/config/settings` | `{"refreshSeconds":300,"cacheSeconds":120,"includeIssues":true}` の一部を保存（API 消費の調整用） |
| GET | `/api/ping` | 二重起動の判定用（`{app, pid}`） |
| POST | `/api/shutdown` | サーバを終了（`pr-monitor-stop.cmd` が使う） |

`127.0.0.1` のみで待ち受け、書き込みと停止は Origin がローカルのときだけ受け付ける。

## API のレート制限（ここだけ注意）

GitHub GraphQL は **5000点/時**。点数は「**要求したノード数**」で決まるので、リポジトリ数と
`maxPrsPerRepo` / `maxIssuesPerRepo` で一気に増える。**1回の取得コストはフッタに「今回 n点」**として出る。

```
1時間の消費 ≒ 1回のコスト × 3600 / refreshSeconds
```

**「進捗」パネルの「GitHub API の残量」に円グラフで残量が出る。** 残量・リセット時刻・
「1回 n点 × 最大 m回/時 = 最大 x点/時」まで数字で出るので、そこで足りるかを判断できる。
残量が 25% を切ると黄色、10% を切ると赤（`⚠` 付き）になり、少ないときは画面上部にも警告が出る。

**その場で調整できる**（同じパネルの下段。`config.json` が書き換わる）。

| 調整 | 効果 |
| --- | --- |
| 更新間隔（1分〜30分 / 自動更新しない） | 1時間の消費がそのまま反比例する |
| 「Issue も取得」を外す（= `includeIssues: false`） | Issue とマイルストンの問い合わせをやめる |
| 監視リポジトリを OFF にする（監視リポジトリパネル） | そのリポジトリを取得しない |
| `maxPrsPerRepo` / `maxIssuesPerRepo` を下げる（`config.json`） | 1回のコストが下がる |

上部の**リポジトリ絞り込みチェックは表示だけ**で、消費は減らない（取得は続く）。

実測の目安: 6リポジトリ・PR 28件・Issue 88件・マイルストン 6件で **1回 24点**
（`refreshSeconds` 300 なら 最大 288点/時）。既定値はこの規模で収まるように決めてある。
0 になると取得自体が失敗し、リセットまで表示できない。

## 既知の癖

- GitHub の `mergeable`（コンフリクト判定）は非同期に計算されるため、初回の問い合わせでは
  `UNKNOWN` が返ることがある。同じ HEAD コミットの直近の確定値をサーバ側で覚えて埋め戻している。
- Draft PR ではワークフローが動かない設定のこともあり、その場合 Actions は「CIなし」になる。
